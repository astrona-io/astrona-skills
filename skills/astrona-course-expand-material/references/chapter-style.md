# Chapter style

- Lead with what the concept is and why it matters.
- Use plain language and define technical terms on first use.
- Prefer “normally,” “commonly,” or “depends on the environment” when exceptions matter.
- Distinguish configuration from verification and link state from end-to-end reachability.
- Treat addresses, hostnames, interface names, and outputs as examples.
- Warn before commands that can interrupt networking or a remote session.
- State whether command-line changes survive a restart.
- Use short tables only for exact comparisons and `text` blocks for compact topologies.
- Do not force identical headings onto every topic.
